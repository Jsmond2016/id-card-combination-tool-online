## 背景与目标

### 背景

入职、开户、政务办理、租房等场景经常需要提交**身份证复印件**。线下复印需要出门找打印店；用手机拍完身份证后自己排版到 A4 纸上很容易出现三类问题：

1. **尺寸不对**：直接用图片编辑器缩放，打印出来比真身份证大或小，窗口常以"复印件与原件不一致"为由退回。
2. **版式不对**：正反面位置错乱、倾斜、留白过多，一张纸只能放一面，浪费纸张。
3. **导出不可打印**：导出的 PDF/图片不是 A4 页面尺寸，打印时被"适合页面"二次缩放，尺寸彻底失真。

### 目标

做一个**纯浏览器端**的在线工具：上传身份证正反面照片 → 裁剪校正 → 按国家标准尺寸排版到 A4 → 导出图片/PDF → 直接打印，且打印结果与真实的身份证复印件规格一致。

### 成功标准

- 用户在 2 分钟内完成"上传 → 排版 → 导出"全流程，无需理解 DPI、像素、毫米换算等概念。
- 导出的 PDF 在 A4 纸上以 **100% 比例**打印后，身份证图像实测尺寸符合所选规格（误差 ≤ 0.5mm）。
- 全流程**零网络上传**，身份证图片不离开用户设备。

## 关键尺寸依据

本项目所有尺寸以毫米（mm）为唯一真值来源，像素值由 DPI 推导（`px = mm / 25.4 × dpi`）。

| 项目 | 标准尺寸 | 说明 |
| ---- | -------- | ---- |
| 第二代居民身份证（物理卡体） | **85.6mm × 54mm** | ISO/IEC 7810 ID-1 标准，圆角半径 3.18mm |
| 身份证复印件（常用规格） | **88mm × 56mm** | 政务、银行等场景沿用的复印件规格，约为原大 103% |
| A4 纸张 | **210mm × 297mm** | 国际标准 A4 |
| 输出精度 | **300 DPI**（默认）/ 150 DPI | A4 @300DPI = 2480 × 3508 px |

> 用户需求中"尺寸必须符合标准，或略小一点也可以"，对应本项目提供的两个规格预设：`88 × 56mm`（默认）与 `85.6 × 54mm`（原大）。两者均 ≤ 复印件标准规格。
>
> **比例差异说明**：`88/56 = 1.5714`，`85.6/54 = 1.5852`，两者并非严格等比缩放关系（88mm 宽对应等比高度应为 55.5mm）。本项目以"规格自身的宽高比"作为裁剪与输出依据，即选择哪个规格，裁剪框与输出就严格是该规格的宽高比，保证输出尺寸精确落在标准值上，不做等比放大导致的尺寸漂移。

## 需求范围

状态取值：`待开发` / `开发中` / `已实现` / `已验证` / `已废弃`

判定口径：`已验证` = 存在可复现的自动化断言或浏览器实测证据；`已实现` = 代码已完成但当前缺少自动化验证手段。具体证据见开发方案文档的「验证结果」。

## 非目标

以下内容**明确不在本期范围**，以避免范围蔓延：

| 项 | 原因 |
| -- | ---- |
| 服务端上传、云端存储、账号体系 | 身份证属高敏感个人信息，任何上传都会引入合规与安全风险，R13 要求零上传 |
| 自动边缘检测（自动识别卡片四角） | 只有"自动找四个角"才需要引入体积庞大的 CV 依赖，且鲁棒性差（卡边与背景同色、反光、阴影都会识别失败）；改为由用户手动拖拽四角（R22），不引入任何依赖即可达到同等的矫正精度 |
| 身份证信息 OCR 识别 | 与"生成复印件"目标无关，且会显著扩大攻击面 |
| 水印内容的合规判定与自动文案 | 水印文字完全由用户自定义（R20）；工具只负责排版与渲染，不提供「什么用途该写什么字样」的建议或校验 |
| 草稿持久化（IndexedDB / localStorage 存图片） | 与隐私优先原则冲突，身份证图片落盘到浏览器存储存在被他人读取的风险，因此选择"刷新即丢弃" |
| HEIC / HEIF 格式转换 | 需额外解码依赖；改为检测到该格式时给出明确提示，引导用户改用系统相册导出 JPG |
| 多页批量处理、多张身份证同时处理 | 本期面向"本人一份复印件"的高频场景 |
